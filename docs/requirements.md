# Требования и критерии приёмки

> Источник требований: `docs/TZ.md` (тестовое задание «копия YouTube»).
> Критерии «что значит работает правильно» сформулированы на основе ТЗ
> и здравого смысла продукта «видеохостинг».

## 1. Глоссарий

| Термин | Значение |
|---|---|
| Гость | Неаутентифицированный посетитель |
| Пользователь | Аутентифицированный аккаунт без особых прав |
| Модератор | Пользователь + право рассматривать жалобы и скрывать/возвращать видео |
| Администратор | Модератор + управление пользователями (назначение ролей, блокировка) |
| Публичное видео | Доступно всем, включая гостей |
| Приватное видео | Доступно владельцу и явно разрешённым пользователям (белый список) |
| Скрытое видео | Заблокировано модерацией; невидимо в лентах, доступно только владельцу и модерации |
| Плейлист | Упорядоченный набор видео одного автора |
| Превью | JPEG-кадр, генерируемый из видео при загрузке |
| Транскод | Единица фоновой обработки видео (перекодирование в MP4/H.264 + превью) |

## 2. Функциональные требования

### FR-1. Главная страница

- **FR-1.1** Лента публичных видео: превью, название, канал, дата публикации, счётчик просмотров.
- **FR-1.2** Лента пагинируется постранично.
- **FR-1.3** Приватные и скрытые видео не попадают в ленту ни при каких условиях.
- **FR-1.4** В шапке — поиск; для гостей — кнопки «Войти» и «Зарегистрироваться».

### FR-2. Просмотр видео

- **FR-2.1** Страница видео: плеер, название, канал, кнопка подписки, лайк/дизлайк, счётчики, описание, дата, просмотры.
- **FR-2.2** Плеер — HTML5 `<video>`; перемотка через HTTP Range-запросы, полноэкранный режим, скорость воспроизведения.
- **FR-2.3** Просмотр засчитывается при старте воспроизведения, не чаще одного раза на зрителя за 24 часа (дедупликация на бэкенде). Гости учитываются наравне с пользователями; дедупликация гостей — по cookie-фингерпринту.
- **FR-2.4** Комментарии: список + форма для аутентифицированных; поддержка ответов (один уровень вложенности).
- **FR-2.5** Лайки/дизлайки: один выбор на пользователя, повторный клик снимает оценку.

### FR-3. Канал

- **FR-3.1** Страница канала: имя, аватар, счётчик подписчиков, кнопка «Подписаться/Отписаться».
- **FR-3.2** Вкладки: «Видео» (публичные + собственные приватные для владельца) и «Плейлисты».
- **FR-3.3** Плейлист: создание, добавление/удаление видео, порядок.

### FR-4. Поиск

- **FR-4.1** Поиск публичных видео по названию (без учёта регистра, ILIKE), пагинация.
- **FR-4.2** Приватные и скрытые видео исключены из результатов поиска для всех, кроме случая FR-2-приватного-доступа.

### FR-5. Загрузка видео

- **FR-5.1** Загружать видео может только аутентифицированный пользователь.
- **FR-5.2** Загрузка: выбор файла, метаданные (название, описание), флаг «приватное», прогресс.
- **FR-5.3** Допустимые форматы на входе: mp4, webm, mkv, mov, avi (проверка по расширению + magic bytes / сигнатуре контейнера).
- **FR-5.4** Лимит размера файла: 512 МБ по умолчанию; значение берётся из переменной окружения `MAX_UPLOAD_SIZE`. Лимит тела запроса в reverse proxy (NGINX `client_max_body_size`) синхронизируется с этим значением при деплое.
- **FR-5.5** После загрузки видео получает статус `uploading → processing → ready` (или `failed`); в лентах появляются только `ready`.
- **FR-5.6** Фоновый воркер перекодирует входной файл в MP4 (H.264 + AAC) и генерирует превью-кадр.

### FR-6. Вход и регистрация

- **FR-6.1** Регистрация: email + пароль + имя канала. Email уникален.
- **FR-6.2** Пароли хранятся только в виде bcrypt-хэша.
- **FR-6.3** Сессии: cookie `session_id` (HttpOnly, SameSite=Lax), серверные сессии с TTL.
- **FR-6.4** Логаут удаляет сессию. Все эндпоинты, требующие авторизации, отдают 401 гостям.
- **FR-6.5** Регистрация сразу открывает сессию (ставит cookie): сценарий «регистрация → загрузка» не требует отдельного входа (решение по ревью m02086; как YouTube/GitHub).

### FR-7. Модерация

- **FR-7.1** Любой аутентифицированный пользователь может подать жалобу на видео (причина из списка).
- **FR-7.2** Очередь модератора: список жалоб со статусами `new → resolved/dismissed`.
- **FR-7.3** Модератор может скрыть видео (`hidden`) и вернуть его (`ready`).
- **FR-7.4** Скрытое видео: владелец видит его на своей странице с пометкой, остальные — нет.

### FR-8. Роли

- **FR-8.1** Роли: `user`, `moderator`, `admin`. Назначает администратор.
- **FR-8.2** Владелец видео — права владельца; модератор — права модерации; пересечений нет.
- **FR-8.3** Приватное видео с белым списком: доступ на просмотр у владельца и перечисленных пользователей (в т.ч. модераторов и админов).

### FR-9. Доступ к приватным видео

- **FR-9.1** Приватное видео доступно: владельцу, пользователям из белого списка, модераторам и админам.
- **FR-9.2** Владелец управляет белым списком на странице видео (добавить/убрать по email или имени).
- **FR-9.3** Прямая ссылка на объект в хранилище не даёт доступа без проверки прав — файлы отдаются через подписанные URL с коротким TTL.

### FR-10. Удаление видео

- **FR-10.1** Владелец может удалить своё видео; модератор/админ — любое.
- **FR-10.2** Удаление мягкое: видео сразу исчезает из лент, поиска и канала; страница видео → 404 для всех.
- **FR-10.3** Фоновый воркер удаляет объекты из хранилища (`raw`, `videos`, `thumbnails`) и завершает удаление записи; сбой очистки ретраится, запись сохраняется до успешной очистки.

### FR-11. UI-стиль

- **FR-11.1** Раскладка максимально близкая к YouTube: шапка с поиском, боковое меню (сайдбар), сетка карточек на главной и в поиске, двухколоночная страница просмотра (плеер и метаданные слева, комментарии справа).
- **FR-11.2** Светлая и тёмная темы: переключатель, выбор сохраняется.
- **FR-11.3** Название и логотип собственные; торговые марки и ассеты YouTube не копируются.

### FR-12. Демо-данные и первый администратор

- **FR-12.1** Seed-скрипт создаёт демо-аккаунты (user/moderator/admin) с фиксированными паролями; пароли указаны в README с пометкой «только для демо».
- **FR-12.2** Seed не запускается в production-режиме (`APP_ENV=production`).
- **FR-12.3** Первый администратор реального деплоя создаётся из переменных окружения (`FIRST_ADMIN_EMAIL`, `FIRST_ADMIN_PASSWORD`) при старте, если админов в системе нет.

## 3. Нефункциональные требования

- **TR-1** Ответ списка ленты на демо-датасете (до 1000 видео) < 300 мс.
- **TR-2** Плеер поддерживает Range-запросы (206 Partial Content).
- **TR-3** Страница видео отвечает < 500 мс.
- **TR-4** Пароли: bcrypt (cost ≥ 10). Сессии — HttpOnly cookie.
- **TR-5** Rate limit на вход/регистрацию/загрузку.
- **TR-6** Всё разворачивается одной командой на чистой Ubuntu.
- **TR-7** OpenAPI-схема доступна на `/docs`.

## 4. Критерии приёмки (Дано / Когда / Тогда)

### 4.1 Загрузка видео

```text
Дано: пользователь аутентифицирован
Когда: загружает валидный mp4 (< 512 МБ) и заполняет метаданные
Тогда: создаётся запись со статусом processing, воркер перекодирует в MP4 + генерирует превью,
       статус становится ready, видео появляется в ленте канала и на главной
```

```text
Дано: пользователь аутентифицирован
Когда: загружает файл с расширением .mp4, но содержимое не является видео
Тогда: загрузка отклоняется с ошибкой 415, запись не создаётся
```

```text
Дано: гость
Когда: открывает страницу загрузки
Тогда: видит требование войти, форма недоступна
```

### 4.2 Приватные видео

```text
Дано: видео приватное, белый список пуст
Когда: другой пользователь открывает URL видео напрямую
Тогда: получает 404, видео отсутствует в лентах и поиске
```

```text
Дано: видео приватное, пользователь U2 в белом списке
Когда: U2 открывает URL видео
Тогда: видео воспроизводится
```

```text
Дано: видео приватное
Когда: неавторизованный запрос пытается получить медиа-URL из хранилища напрямую
Тогда: доступ запрещён; медиа доступны только через подписанный URL с проверкой прав
```

### 4.3 Роли

```text
Дано: пользователь с ролью user
Когда: открывает очередь модерации
Тогда: получает 403
```

```text
Дано: пользователь с ролью moderator
Когда: открывает очередь модерации
Тогда: видит список жалоб и может скрыть/вернуть видео
```

```text
Дано: администратор
Когда: назначает пользователю роль moderator
Тогда: пользователь получает доступ к очереди модерации без пересоздания сессии
       (роль проверяется на каждом запросе по данным БД)
```

### 4.4 Модерация

```text
Дано: пользователь смотрит видео
Когда: подаёт жалобу «спам»
Тогда: жалоба появляется в очереди модератора со статусом new
```

```text
Дано: модератор рассматривает жалобу
Когда: нажимает «Скрыть видео»
Тогда: видео получает статус hidden, исчезает из лент и поиска,
       владелец видит его на своём канале с пометкой «скрыто модерацией»
```

```text
Дано: скрытое видео
Когда: модератор нажимает «Вернуть»
Тогда: видео снова публично, связанная жалоба закрыта
```

## 5. Объём и приоритеты

### P0 — вертикальный срез (сквозной сценарий)

1. Регистрация, вход, сессии; Swagger на `/docs`; healthcheck.
2. Загрузка видео + фоновый транскод + превью.
3. Главная лента + страница просмотра (плеер, Range).
4. Лайки и комментарии.
5. Гостевые просмотры с дедупликацией по cookie.

### P1 — обязательные требования сверх P0

6. Каналы + подписки; поиск по названию.
7. Приватные видео + белый список; роли + модерация (жалобы, скрытие/возврат).
8. Удаление видео владельцем (мягкое удаление + очистка хранилища воркером).
9. Плейлисты.
10. UI, близкий к YouTube: шапка с поиском, сайдбар, сетка карточек, двухколоночный просмотр, светлая и тёмная темы.
11. Деплой одной командой + seed-скрипт (фиксированные демо-пароли в README с пометкой «только для демо»; seed отключён в production; первый админ из переменных окружения).

### P2 — если останется время (не блокирует сдачу)

12. Автовыбор темы по системным настройкам, история просмотров, фильтры ленты.

### Отложено и почему

| Что | Почему |
|---|---|
| Транскод в несколько разрешений (240/360/720p) | Один прогрессивный MP4 480p достаточен для проверки; мульти-битрейт усложняет воркер и не проверяется |
| WebSocket-прогресс загрузки | Достаточно опроса статуса задачи; SSE/WS — лишняя инфраструктура |
| Субтитры, главы, рекомендательный алгоритм | Не требуются ТЗ, не проверяются |
| CDN | Не требуется, всё в локальном хранилище |
| REST-пагинация курсором | Классический limit/offset достаточен на объёме демо-данных |
| Email-подтверждение регистрации | Не требуется для проверки сценария |
| i18n | Один язык интерфейса (русский) достаточен для проверки |

## 6. Допущения

1. «Простой фронт» трактуется как серверный рендеринг Jinja2-шаблонов без JS-фреймворка; минимум JS для прогресса загрузки, лайков и переключения темы.
2. «Одна команда» развёртывания — bash-скрипт `deploy.sh`, который ставит Docker + Docker Compose на чистой Ubuntu и поднимает весь стек.
3. Объектное хранилище — S3-совместимое (Silo, форк MinIO — ADR-001), разворачивается в том же Compose-стеке.
4. Модерация — только пост-модерация по жалобам (без автоматических проверок контента).
5. Демо-медиа для seed-скрипта: маленькие синтетические файлы, генерируемые скриптом (ffmpeg testsrc), чтобы не тащить бинарники в git.
6. Плейлисты принадлежат одному автору; совместный доступ к плейлистам не поддерживается.
7. Комментарии — один уровень вложенности ответов.
8. Доступ к приватному видео по прямой ссылке отдаёт 404 (не 403), чтобы не раскрывать факт существования видео.
9. Rate limit входа: в dev/юнит-режиме счётчик in-memory (интерфейс `RateLimiter`), в production — Redis (та же семантика окна; соответствует ADR-002).
10. Хеширование паролей — пакет `bcrypt` напрямую (cost 12): passlib 1.7.4 не поддерживается и несовместим с bcrypt 5.x (ошибка «password cannot be longer than 72 bytes» на тестовых векторах). Формат хеша и cost не отличаются.
11. Поиск по названию — ILIKE + pg_trgm: расширение входит в official-образ `postgres:16-alpine` (contrib ставится в alpine-варианте), миграция `d9e0f1a2b3c4` создаёт extension и GIN-индекс.
12. Воркер транскода: ffmpeg таймаут 600s с kill процесса, arq `job_timeout=660`, `max_jobs=2`; падение этапа → `videos.failure_reason`. таймауты/колонка — миграция `c8d9e0f1a2b3`.
13. Rate limiter и arq-пул создаются один раз в lifespan и хранятся в `app.state` (в dev in-memory лимитер — синглтон, состояние не теряется между запросами); закрываются на shutdown.
14. Гостевой фингерпринт — cookie `guest_id` длиной 1..64 из `[A-Za-z0-9_-]`; прочее значение заменяется серверным `token_urlsafe(24)`.

## 7. Решения по открытым вопросам (утверждены ревьюером 2026-11-11)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Гостевые просмотры | Считать (P1); дедупликация гостей по cookie-фингерпринту |
| 2 | Лимит файла | 512 МБ, значение из переменной окружения; лимит тела запроса в reverse proxy синхронизирован |
| 3 | Удаление видео | Входит в объём (P1): мягкое удаление, воркер удаляет объекты из хранилища |
| 4 | UI-стиль | Максимально близкая к YouTube раскладка (шапка с поиском, сайдбар, сетка карточек, двухколоночный просмотр, светлая и тёмная темы); название и логотип свои |
| 5 | Демо-креды | Фиксированные пароли seed-аккаунтов в README с пометкой «только для демо»; seed не запускается в production; первый администратор реального деплоя — из переменных окружения |
