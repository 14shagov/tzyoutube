# ADR-001: Объектное хранилище — MinIO

Статус: принято.

## Контекст

По ТЗ нужна загрузка видео до 512 МБ, транскодирование, превью и раздача с поддержкой Range-запросов. Хранить большие бинарники в PostgreSQL нельзя; система должна разворачиваться одной командой на чистой Ubuntu без внешних облачных аккаунтов.

## Варианты

1. **Файловая система (том контейнера).** Просто, но нет presigned URL и bucket-политик: пришлось бы самому писать раздачу с Range и проверку прав в NGINX/приложении; сложнее бэкап.
2. **MinIO (self-hosted, S3-совместимое).** Presigned URL, политики бакетов, Range из коробки, официальный SDK (minio-py), S3-совместимость на будущее.
3. **Внешний S3 (AWS).** Нарушает требование самодостаточности (чистая Ubuntu, одна команда), требует аккаунт и платёжные данные.

## Решение

MinIO в том же Docker Compose-стеке. Бакеты: `raw` (приватный, исходники), `videos` (приватный, транскоды), `thumbnails` (public-read). Порты MinIO не публикуются наружу — доступ через NGINX `/media/` или из внутренней сети.

## Последствия

- Плюс: presigned URL и политики доступа бесплатно; Range/206 отдаёт сам MinIO; локальная разработка идентична S3.
- Минус: ещё один сервис в стеке (память ~сотни МБ) — приемлемо для тестового задания.
- Минус: это не CDN — для ТЗ достаточно.
