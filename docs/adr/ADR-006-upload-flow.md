# ADR-006: Загрузка видео — multipart через API

Статус: принято.

## Контекст

Лимит файла 512 МБ, обязательна валидация (расширение + magic bytes + размер) до попадания файла в хранилище; в браузере нужен прогресс-бар.

## Варианты

1. **Presigned PUT: браузер → S3-хранилище напрямую.** Разгружает API, но файл попадает в хранилище до какой-либо проверки — мусор/вредоносы пришлось бы чистить пост-фактум; плюс CORS на хранилище.
2. **Multipart POST /api/videos, стримом в хранилище.** Одна точка валидации на входе (первые байты — magic bytes, размер — счётчиком), прогресс в браузере через `XMLHttpRequest.upload.onprogress`.

## Решение

Вариант 2. API принимает multipart, читает файл стримом (не в память), кладёт `raw/<uuid>`, считает SHA-256, создаёт запись `videos.status='processing'`, ставит задачу воркеру. Лимит `MAX_UPLOAD_SIZE` enforcement: NGINX `client_max_body_size` + счётчик в приложении.

## Последствия

- Плюс: валидация до сохранения; один код-путь; прогресс работает без сторонних библиотек.
- Минус: трафик проходит через API-процесс — на масштабе тестового задания приемлемо; при росте можно добавить presigned PUT с post-validate, интерфейс `core/storage.py` это не блокирует.
