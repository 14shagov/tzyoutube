# ADR-009: Превью — только presigned URL, бакет `thumbnails` приватный

Статус: принято. Отменяет часть ADR-001 (п.24) и ADR-003 (п.17) про public-read превью через `/media/thumbnails/`.

## Контекст

Ручная проверка (m00002, п.1): 118 запросов `GET /media/thumbnails/<id>.jpg` вернули 403 AccessDenied — бакет `thumbnails` приватный, а `ensure_buckets` только создаёт бакеты и никогда не ставит политику. Требования: приватные, скрытые, не-ready и удалённые видео НИКОГДА не отдают превью анонимно; для публичных ready-видео превью отдаётся без ошибок.

## Варианты

1. **Public-read префикс в бакете только для превью публичных видео** (политика в `ensure_buckets`, идемпотентно). Проблема: политика бакета действует на весь бакет/префикс — любой ключ доступен анонимно по id через nginx `/media/thumbnails/<key>`. Скрытому/приватному/не-ready видео превью утекает по подобранному id, пока воркер его не перезаписал. Защита «только публичные» требует, чтобы ключ однозначно кодировал публичность, чего нет.
2. **Presigned URL для всех превью** (выбран). Бакет остаётся приватным; nginx `/media/thumbnails/` продолжает 403 (теперь это deny-by-design). Подписанная ссылка выдаётся только после проверки доступа (`can_view`), TTL как для видео.

## Решение

Вариант 2.

- `ensure_buckets` НЕ вызывает `set_bucket_policy` — бакет приватный (тест-пин: `set_bucket_policy.assert_not_called()`).
- `_thumb_url(video, storage)` в `api/videos.py` и `_thumb(video, storage)` в `pages.py` всегда возвращают `storage.presigned_get(BUCKETS["thumbnails"], key, response_headers={"response-content-type": "image/jpeg"}, private=is_private)`; без ключа — `None`.
- Вызывающий код (feed/search/video_card/страницы) сначала проверяет доступ, затем подписывает — аноним никогда не получит валидную ссылку на чужое превью.
- Presign — офлайн HMAC (регион зафиксирован), без сети; цена на ~24 карточки negligible.
- NGINX `location /media/thumbnails/` оставлен (теперь deny): прямой доступ к объектам запрещён.

## Consequences

- Плюс: нет утечки превью по id; единая политика с видео (ADR-003).
- Минус (принято): подпись живёт TTL — расшаренная ссылка на превью публичного видео работает до истечения TTL; для приватных TTL короче. Кэш nginx `Cache-Control` на `/media/` более не используется для превью.
- Уже загруженные видео: повторная генерация превью — `scripts/regen_thumbnails.py` (прогон воркера по ready-видео), либо миграция данных.

## Worker: кадр не с самого начала

`thumbnail_offset_seconds(duration)`: 10% длительности, но не больше 1 с и не за концом; неизвестная длительность → 1 с. `build_ffmpeg_args(..., thumb_offset=...)` подставляет `-ss {ss}`. Ранее кадр брался с `-ss 1` фиксированно — для коротких роликов это мог быть чёрный кадр в самом начале.

## UI: заглушка без inline-JS

Если превью не загрузилось (протухшая подпись, удалённый объект), `app.js` (внешний, CSP `script-src 'self'`) вешает `addEventListener("error")` на `.thumb img, .rec-thumb img` и подменяет `src` на `/static/thumb-ph.svg`. В шаблонах нет `onerror=`/`onload=`.
