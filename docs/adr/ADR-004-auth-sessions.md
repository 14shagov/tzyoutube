# ADR-004: Авторизация — серверные сессии в БД

Статус: принято.

## Контекст

Фронт — SSR без SPA. Нужны: мгновенный отзыв сессии (логаут, блокировка пользователя), актуальная роль на каждом запросе (user/moderator/admin), флаг `is_blocked`. Сессия живёт 14 дней.

## Варианты

1. **JWT.** Stateless, но отзыв токена до истечения — отдельная инфраструктура (denylist), роль зашита в токене и устаревает; для SSR выгоды нет.
2. **Серверные сессии: таблица `sessions` в PostgreSQL + cookie `session_id`.** Отзыв = DELETE строки; роль и блокировка читаются из БД на каждом запросе.

## Решение

Вариант 2. Cookie: `session_id` = UUID первичного ключа `sessions`, флаги `HttpOnly`, `SameSite=Lax`, `Secure` в проде; TTL 14 дней. Зависимость FastAPI `get_current_user` делает один запрос к БД: JOIN users + sessions, отбрасывает просроченные и заблокированных.

## Последствия

- Плюс: мгновенный логаут и блокировка; простая логика; нет криптографии на своей стороне.
- Минус: +1 запрос к БД на каждый запрос — на масштабе тестового задания незаметно.
