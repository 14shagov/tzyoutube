# ADR-003: Раздача видео — presigned URL

Статус: принято.

## Контекст

Видео бывают приватными (владелец + белый список + модератор/админ). Прямой доступ к хранилищу должен быть закрыт; плееру нужны Range-запросы для перемотки.

## Варианты

1. **Стримить через API (прокси).** Полный контроль и отзыв в каждый момент, но весь трафик идёт через Python-процесс, он же держит соединения и буферизирует; масштабируется плохо.
2. **Отдавать напрямую через NGINX → хранилище без подписи.** Нет авторизации на уровне объекта — утечка приватного контента.
3. **Presigned GET URL c TTL после проверки прав.** Приложение проверяет `check_video_access` и выдаёт короткоживущую ссылку; байты отдаёт S3-хранилище (Silo), включая Range/206.

## Решение

Вариант 3: presigned GET с TTL 3600 с для публичных / 900 с для приватных (`PRESIGNED_TTL_SECONDS` / `PRESIGNED_TTL_PRIVATE_SECONDS`), выдача только после `check_video_access`. Превью публичных видео — из бакета `thumbnails` (public-read) через NGINX `/media/thumbnails/`; превью приватных — presigned. Бакет `raw` не раздаётся никогда.

### Host presigned URL за reverse proxy

Сигнатура S3 SigV4 покрывает метод, host, путь — подпись, вычисленная для `silo:9000`, не валидна для запроса через `example.com`. Поэтому:

- приложение держит **два клиента S3**: внутренний (`S3_ENDPOINT=silo:9000`) для PUT/DELETE и внешний (`S3_PUBLIC_ENDPOINT=<host>, видимый браузеру>:80`) — только для генерации presigned URL;
- NGINX публикует `location /videos/` и `location /thumbnails/`, проксирует на `silo:9000` **без rewrite** и с `proxy_set_header Host $host` — хранилище принимает подпись, вычисленную для публичного host;
- в dev/`localhost` те же правила работают с `S3_PUBLIC_ENDPOINT=localhost`.

## Последствия

- Плюс: API не гоняет медиа-трафик; Range и перемотка работают из коробки; подпись валидна именно для внешнего маршрута.
- Минус (принятый остаточный риск): получатель ссылки может расшарить её на срок TTL (4 ч). Задокументировано в security.md; сокращение TTL ухудшает UX долгих просмотров, альтернатива — прокси через API — заметно дороже по ресурсам.
