# Безопасность

## 1. Модель угроз

| № | Угроза | Вектор | Вероятность / влияние |
|---|---|---|---|
| T1 | Подбор пароля / credential stuffing | Массовые попытки входа и регистрации | Высокая / критично (угон аккаунта) |
| T2 | XSS | Вставка HTML/JS в комментарии, названия, описания каналов и видео | Средняя / критично (кража сессии, дефейс) |
| T3 | IDOR | Прямые запросы к чужим приватным видео через /api/videos/{id} и /media | Средняя / критично (утечка приватного контента) |
| T4 | Утечка по прямой ссылке на хранилище | Раздача медиа-объектов без проверки прав | Средняя / критично |
| T5 | Вредоносные загрузки | Файл-полиглот, вредоносный «видео»-контейнер | Средняя / высокое |
| T6 | Секреты в репозитории | .env, ключи в коммитах и логах | Средняя / критично |
| T7 | Повышение привилегий | Использование роли из устаревшей сессии без сверки с БД | Средняя / критично |
| T8 | Спам жалобами/комментариями | Массовая подача жалоб и комментариев | Низкая / среднее |
| T9 | Исчерпание ресурсов | Сверхкрупный файл, флуд запросами | Средняя / среднее |

## 2. Меры

### 2.1 Пароли и вход (T1)

- Хэширование bcrypt, cost 12.
- Сессии: HttpOnly + SameSite=Lax cookie `session_id`, TTL 14 дней; серверные записи в таблице `sessions`.
- Rate limit (в приложении): 5 неудачных попыток входа с одного IP за 10 минут → 429; 3 регистрации в час с IP.
- Ошибка входа — единый generic-ответ, не раскрывающий существование email.
- Логаут удаляет запись сессии в БД.

### 2.2 Сессии и токены (T7)

- Cookie `session_id` — UUID записи БД, не подпись и не JWT: отзыв мгновенный удалением записи.
- Роль и флаг блокировки проверяются из БД на каждом запросе; сессия роль не кэширует.
- Все cookie-флаги: `HttpOnly`, `SameSite=Lax`, `Secure` (в проде за NGINX — через `Proxy-Affected` заголовки; локально без TLS).

### 2.3 Валидация загрузок (T5, T9)

- Белый список расширений: mp4, webm, mkv, mov, avi.
- Проверка magic bytes / сигнатуры контейнера, а не только расширения.
- Лимит размера `MAX_UPLOAD_SIZE` (512 МБ), enforced на уровне NGINX (`client_max_body_size`) и приложения.
- Загруженный файл не исполняется: отдаётся только как объект S3-хранилища; ffmpeg работает с копией в tmp-каталоге воркера.
- Имена объектов — UUID, сгенерированные сервером; пользовательское имя файла не используется.

### 2.4 XSS (T2)

- Jinja2 автоэкранирование по умолчанию; нигде не отключать (`| safe` под запретом без явной причины).
- Пользовательский контент (комментарии, названия, описания) экранируется на выводе.
- REST API возвращает JSON; экранирование не требуется, но строки нормализуются и обрезаются по длине.
- Content Security Policy базового уровня: `default-src 'self'` (медиа с домена хранилища — `img-src`/`media-src` явно).

### 2.5 IDOR и приватность (T3)

- Проверка доступа в сервисном слое для каждого эндпоинта, работающего с video_id / channel_id.
- Приватное/скрытое видео для неавторизованных и без права доступа → 404 (не раскрываем существование).
- Белый список `video_acl` проверяется в том же сервисном методе `check_video_access`.
- Тесты на IDOR обязательны (см. testing.md).

### 2.6 Раздача медиа (T4)

- Presigned GET URL с TTL 4 часа; выдача только после `check_video_access`.
- Бакет `raw` закрыт полностью; публичная политика только на `thumbnails`.
- NGINX проксирует `/media/` → хранилище; прямые порты хранилища наружу не публикуются.

### 2.7 Секреты (T6)

- Все секреты — переменные окружения (`.env`, генерируется `deploy.sh` при первом запуске).
- В репозитории только `.env.example` с плейсхолдерами; `.env` в `.gitignore` с первого коммита.
- Перед каждым коммитом — просмотр `git diff --cached`.
- Секреты не логируются; логирование настроено на уровни событий, а не на дампы запросов.

### 2.8 CORS

- Фронт и API — один origin (NGINX), поэтому CORS закрыт: запрещаем wildcard, разрешён только собственный origin при необходимости.

### 2.9 Права на хранилище

- Ключи приложения в хранилище — минимальные: read/write в нужных бакетах, отдельная пара для воркера не требуется (один сервисный аккаунт на приложение).
- Root-ключи хранилища используются только при первичной инициализации бакетов.

## 3. Что осознанно не делаем (и почему)

| Мера | Почему отложена |
|---|---|
| 2FA | Не проверяется сценарием, не успеваем по сроку |
| TLS-сертификаты | Тестовая VM, HTTP за NGINX; LetsEncrypt требует домен — оставлено как опция deploy.sh |
| WAF | Избыточно для тестового задания |
| Автоматический антивирусный скан загрузок | Требует ClamAV в стеке; фиксируем как будущее улучшение |
